# Tree placement and world features

Status: proposed. The tree builder (`src/gen/trees/treeBuilder.js`), the tree gallery (`?world.generator=trees`,
`scenarios/index.html?name=trees`) and placement in the climate generator (`src/gen/collection/climate.js`) are done.

## Problem

Trees in the real world (`NoiseChunkGenerator`) need to:

- stand anywhere, including on chunk edges, with the trunk in one chunk and leaves in others,
- be allowed to stand close to each other, with touching or overlapping crowns,
- get their base height from the terrain, also when the trunk column belongs to another chunk.

Every chunk is generated on its own, so every chunk that a tree reaches must come up with exactly the same tree.

## What already works

`TreeBuilder.generate(chunk, baseH, baseX, baseY, seed, species)` takes the tree base in chunk local coordinates,
which may be outside the chunk (negative or `>= 32`, also vertically). It writes only blocks inside the chunk.
A tree is built whole from its seed in its own grid (and kept), then the part in the chunk is written, so the parts
of a tree generated by different chunks match.

- Size limits: `TreeBuilder.MAX_RADIUS` (7), `MAX_HEIGHT` (19), and
  `TreeBuilder.canReachChunk(baseH, baseX, baseY)`.
- Merge rules: leaves only fill empty blocks, trunks overwrite leaves. Overlapping trees give the same result
  in any order, so touching trees are consistent across chunks.

## Proposed design: three layers, each a pure function of world coordinates

### 1. Height field

- `heightAt(wx, wy)` for any column, plus a cached tile per chunk column (chunk plus a margin of at least
  `MAX_RADIUS`, so trees that reach the chunk can read their base height).
- The terrain fill, tree placement and later features all read heights from it.
- The column cache also speeds up generation: currently every chunk at every z level of the same column
  (about 17 levels in view) recomputes the same noise height map.
- **Pitfall:** `GenNode.gen(x, y, iteration)` caches the last value by `iteration`. `NoiseChunkGenerator` passes
  `y * 32 + x`, which only works because consecutive calls never repeat a value. Lookups at arbitrary positions
  must use a unique, increasing counter, or they can get a stale value.

### 2. Tree placement

- The world is split into cells (for example 6×6). Each cell has at most one candidate, with a random offset inside
  the cell, a species and a seed, all from a hash of the cell coordinates.
- Candidates are accepted or rejected by a density noise (forests and clearings) and terrain rules from the
  height field: not under water, not on sand, not on steep slopes. The species can depend on height or biome
  (pines higher up, bushes at forest edges).
- Spacing: a candidate checks the candidates in its 3×3 neighbouring cells and is dropped when one with
  higher priority (from its hash) is closer than the minimum distance. One parameter controls how close trees
  can be: touching crowns, a gap between trees, or very dense forest.
- The result depends only on hashes and the height field, so any chunk asking for the trees near it gets the
  same list. API idea: `treesNear(chunkPos)` returns every tree within `MAX_RADIUS` of the chunk in x and y,
  with base position, species and seed.

### 3. Chunk composition

- Write terrain from the height field first, then every tree from the placer with `TreeBuilder`.
- Order independent merge (terrain first, then trunk over leaves, leaves only into empty blocks) keeps
  touching trees the same in every chunk.
- Trees crossing a vertical chunk border are handled the same way: a base 3 blocks below the chunk bottom is
  just `baseH = -3`.

### Out of scope for now

- Features that depend on the final blocks of neighbouring chunks (for example trees growing on other structures).
- Player edits.

## Suggested order

1. `HeightField` with the column cache, and switch `NoiseChunkGenerator` to it. The terrain must stay identical;
   generation should get faster.
2. `TreePlacer` with spacing and terrain rules. Use it in the tree test generator too, to try settings on flat ground.
3. Trees in the default world.

After each step, verify in Node that neighbouring chunks agree at their borders (same approach as the tree
generator check).

## Open questions

- Should crowns be allowed to touch by default (forest look), or should trees keep a minimum gap?
- Cell size and density per biome.

## Related issue found

`NoiseChunkGenerator` places `BLOCK_IDS.GRASS_SHORT`, which does not exist (only `GRASS_SHORT_0` and
`GRASS_SHORT_1` do). It writes `undefined`, which becomes 0, so the default world never gets short grass.
